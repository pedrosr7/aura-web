# Aura — marketing / early-access site

Single-file static landing page for the Aura fitness app. Built to match the app's
real brand (neon yellow `#CCFF00` on dark `#0E0E0E`, JetBrains Mono headings, Tabler icons).

```
aura-web/
├── index.html              # landing / early-access (the marketing page)
├── coaches.html            # for coaches: the five-step tour, pricing and FAQ (EN) · coaches.es.html (ES)
├── privacy.html            # privacy policy   (EN) · privacy.es.html (ES)
├── terms.html              # terms of service (EN) · terms.es.html (ES)
├── support.html            # support + FAQ    (EN) · support.es.html (ES)
├── delete-account.html     # account deletion (EN) · delete-account.es.html (ES)
├── 404.html                # 404 + doubles as the /share/<token> deeplink landing
├── plan.html               # the /plan link's bridge page: stores on a phone, a QR on a computer
├── .nojekyll               # REQUIRED — without it Jekyll hides .well-known/
├── .well-known/            # app deeplink verification (Android + iOS)
├── tests/                  # node --test tests/*.test.mjs (Node 22 or newer, no dependencies)
└── assets/
    ├── js/                 # plan-bridge.js (the /plan page's logic) and qrcode.js (qrcode-generator, vendored)
    ├── aura_logo.png
    ├── coach/{es,en}/      # the coaches page's clips: MP4 + JPG poster per step
    ├── og/                 # link-preview images (1200×630 JPG) for og:image / twitter:image of the coaches pages
    └── captures/           # real in-app screenshots used on the landing page
        ├── cap-pulse.png       # hero — daily home
        ├── cap-planning.png    # showcase — weekly plan
        ├── cap-newsession.png  # showcase — new session
        ├── cap-coach.png       # showcase — live workout timer
        ├── cap-log.png         # showcase — training log
        └── cap-insights.png    # showcase — session review
```

Every content page has an EN/ES pair with a language toggle in the header.
The older `screen-hub/plan/log.png` files are no longer referenced.
Screenshots are localized: `assets/captures/*.png` (Spanish app UI) feed `index.es.html`;
`assets/captures/en/*.png` (English app UI) feed `index.html`.
`WEB_HANDOFF.md` and the `appstore-*` files are internal tooling and are
**excluded from the repo** via `.gitignore`.

## Coaches page clips

The clips on `coaches.html` are not screen recordings: they are the app's real composables
rendered frame by frame with invented people (Aura repo, `CoachFlowWebShotTest` and
`AthleteFlowWebShotTest`, assembled by `scripts/webshot-coach-reels.sh`). To refresh them after a
UI change, rerender there and copy `clips/{es,en}/[1-5]-*.mp4` and `*.jpg` into `assets/coach/{es,en}/`.
The page says they show sample data, and that the alert in step 4 is a recreation.

The page plays them as a tour on one phone: each clip runs to the end and hands over to the next,
and only the clip on screen and the next one are downloaded. The script's `all.mp4` overview is not
used. The prices are the app's coach plans (free up to 3 athletes, then 19,99 / 39,99 / 79,99 € a
month for 20 / 60 / 200); if they change in the app, change them on both pages, FAQ included.

## Link previews

`assets/og/coaches-{es,en}.jpg` are what Instagram, WhatsApp and the like show when someone shares
`coaches.html` or `coaches.es.html`: the page's headline plus a frame of the «it lands» clip (4-arrives, at
3 s) in a phone, 1200×630, well under WhatsApp's 300 KB. They are not generated by the site: if the
headline or that screen changes, remake them. Chat apps cache a link's preview, so to see a new one on a URL
that was already shared, add a throwaway parameter (`?v=2`).

## Analytics

Visits are counted with Umami Cloud (free Hobby plan, no cookies). Its tag is in the `<head>` of `index` and
`coaches` (ES and EN); the Website ID is the UUID in that tag, and the dashboard is at cloud.umami.is. The tag has
`data-domains` so local previews are not counted and `data-do-not-track` so a browser's Do Not Track is honored.
Section 10 of the privacy policy describes it; if the provider changes, change that text too.

To know who opened a link, tag it with who it is for: `coaches.es.html?utm_source=<instagram-handle>` (a new URL
also makes chat apps fetch a fresh link preview). The dashboard's UTM report then splits the visits by source.

The coaches pages also send these events, from `data-umami-event` attributes and the page script. Each one fires
once per page view, except the clicks:

| Event | Props | When |
|---|---|---|
| `tour_step` | `step` 1-5, `by` auto or tap | the clip on the phone changes, or the phone is first on screen |
| `tour_end` | | the last clip plays to the end |
| `view_pricing` | | the prices are a quarter on screen |
| `start_click` | `loc` nav, hero or pricing | «Empezar» (on a phone it goes straight to its store) |
| `store_click` | `os` | a store badge |
| `mail_click` | `loc` pricing, faq or footer | any of the mail links |

If the Umami script is blocked or late, the events are dropped or held until it loads; the page does not care.


El orden y los titulares siguen el relato de la landing: hoy → importar →
entrenar → progreso → la pizarra → tu coach → planning (Pro, al final).

## App deeplinks (`/share/<token>`)

`.well-known/` holds the Android + iOS verification files that let share links
open the app instead of the browser; `404.html` is the fallback landing shown
when the app isn't installed (GitHub Pages doesn't map dynamic paths, so the
404 handler doubles as the `/share/<token>` page).

⚠️ `.nojekyll` must stay — without it Jekyll excludes dot-directories and
`.well-known/` 404s, silently breaking every deeplink.

Setup + troubleshooting playbook: `agents/docs/share_deeplink_setup.md` in the
**Aura** repo.

## The /plan link (contract with the app)

The link CatchUp's «Prepárala con Aura» page hands to the app, so the onboarding opens with the athlete's answers in
place. CatchUp writes it, the app reads it (`PlanLink.kt` in the Aura repo), and this site is only the bridge: `plan.html`
serves `/plan` and reads none of the answers.

```
https://aura.pampaiter.com/plan?c=<id>&d=<date>&t=<type>&cat=<id>&lvl=<level>&days=<days>&dur=<minutes>&eq=<kit>&hard=<parts>&src=<origin>
```

Every parameter is optional. A value the app cannot read is left out of the prefill, and the onboarding asks that step.

| Parameter | Value | What the app does |
|---|---|---|
| `c` | The competition's id in CatchUp's list (`hyrox-madrid`): letters, digits, `.`, `_` and `-`. | Picks the competition. If it is not in the list the app refreshes the list once, and if it is still missing it asks. |
| `d` | The competition's date, `YYYY-MM-DD`. | Used only when `c` is not in the list: with a valid `t` and a date of today or later, the competition is added as «not listed». |
| `t` | The type: `CROSSFIT_OPEN`, `HYROX`, `HYBRID`, `OLYMPIC_LIFTING`, `POWERLIFTING` or `OCR`. | The type of a competition that is not listed (see `d`). |
| `cat` | The category's id inside that competition (`pro`, `open`). | Picks the category, ignoring case. |
| `lvl` | `BEGINNER`, `INTERMEDIATE`, `ADVANCED` or `COMPETITOR`. | Answers the level. |
| `days` | The training days as ISO weekdays, `1` Monday to `7` Sunday, comma-separated (`1,3,5`): two to six different days. | Answers the days. |
| `dur` | The session length in minutes: `45`, `60`, `90` or `120`. | Answers the duration. |
| `eq` | `box`, `gym` or `home`. | Answers the equipment with that place's kit. |
| `hard` | What costs the athlete most: up to two of `running`, `strength`, `gymnastics` and `engine`, comma-separated. An empty value (`hard=`) means «no one in particular». | Answers «¿qué te cuesta más?». |
| `src` | Who sent the visit (`catchupheats`): letters, digits, `.`, `_` and `-`. | Read, and not used yet. |

- Keys are read in any case and the first one of a key wins. Anything else in the link (`utm_source`, `fbclid`) is ignored.
- The start of the plan is not in the link: the app works it out from the competition's date and the level. There is no
  `int` parameter.
- The link carries no personal data, only what the athlete picked on CatchUp's page.
- Two forms open the app: the https link above (App Links and Universal Links) and the same query on `aura://plan`.
  The bridge page's «already installed» button uses the second, because iOS does not hand a link of the page's own
  site to the app.

Examples:

```
https://aura.pampaiter.com/plan?c=hyrox-madrid&d=2026-12-05&t=HYROX&cat=pro&lvl=intermediate&days=1,3,5&dur=60&eq=box&hard=running,strength&src=catchupheats
https://aura.pampaiter.com/plan?c=hyrox-madrid&src=catchupheats
https://aura.pampaiter.com/plan?c=hyrox-madrid&lvl=advanced&days=2,4&dur=90&eq=gym&hard=
https://aura.pampaiter.com/plan?d=2026-12-05&t=OCR&lvl=beginner&days=2,4,6&dur=45&eq=home&src=catchupheats
```

What the link does where it lands:

- **Aura installed:** the phone opens the app, not this site. Android: the `/plan` path in the app's manifest, verified
  through `assetlinks.json`. iPhone: `/plan` in `.well-known/apple-app-site-association`; Apple refreshes that file on its
  own, so a phone that already has Aura may open the page for a while, and its «already installed» button covers it.
- **A phone without Aura:** `plan.html` shows the visitor's store first, then the other, and the button «¿Ya la
  instalaste? Vuelve a abrirla aquí», which opens `aura://plan?…` with the same answers, untouched.
- **A computer:** a QR code of the whole https link, drawn in the browser by `assets/js/qrcode.js` (qrcode-generator 1.4.4,
  MIT, unchanged: sha-256 `18ae399f81182bc9de916e9c77b195df20cc58d6f2d55a62b085a299f1bf1780`), so the answers reach no
  other service.
- The page is Spanish for a browser in Spanish and English for the rest, keeps nothing, counts nothing, and is `noindex`
  and out of the sitemap.
